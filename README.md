<h1 align="center">Video to MP3 Downloader</h1>

<p align="center">
  웹페이지에서 재생한 영상·오디오를 자동으로 모아 두었다가,<br>
  <b>MP3로 한꺼번에 변환해서 저장</b>하는 크롬 확장 프로그램입니다.
</p>

---

## 주요 기능

- **자동 수집**: 영상을 재생하면 미디어 주소가 수집함에 자동으로 쌓입니다. (재생을 몇 초만 해도 됩니다)
- **일괄 변환**: 수집함에서 여러 개를 선택해 한 번에 MP3로 변환·저장합니다.
- **백그라운드 처리**: 변환은 크롬의 백그라운드 문서(offscreen)에서 실행되어, **수집함 탭을 새로고침하거나 닫아도 계속 진행**됩니다.
- **빠른 처리**
  - 긴 오디오를 말 사이의 조용한 지점에서 잘라 **여러 CPU 코어로 병렬 인코딩**
  - 서버가 지원하면 **여러 연결로 나눠서 다운로드** (연결 수 선택 가능)
  - 항목마다 다운로드 속도(MB/s)와 진행 단계 표시
- **저장 위치 지정**: 원하는 폴더를 직접 선택하거나, 기본 다운로드 폴더 안의 하위 폴더로 저장
- **정리 기능**: 완료된 항목은 선택 해제 후 아래 "완료" 구역으로 이동, 파일명 편집, `01_`, `02_` 번호 붙이기
- **Referer 자동 처리**: 영상 서버가 "플레이어 페이지를 거친 요청만 허용"하는 경우(HTTP 403)를 처리

## 설치

1. 이 저장소를 내려받습니다.
   ```bash
   git clone https://github.com/kim-milre/video-to-mp3-downloader.git
   ```
   (또는 `Code → Download ZIP`으로 받아 압축을 풉니다.)
2. 크롬 주소창에 `chrome://extensions` 를 입력합니다.
3. 오른쪽 위 **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드합니다**를 누르고, 이 저장소 폴더(`manifest.json`이 있는 폴더)를 선택합니다.
5. 툴바에서 퍼즐 모양 버튼 → 이 확장 프로그램의 **핀 고정**을 누르면 아이콘이 항상 보입니다.

> 코드를 수정한 뒤에는 `chrome://extensions` 에서 확장 프로그램의 새로고침(↻) 버튼을 눌러야 반영됩니다.

## 사용 방법

### 1) 영상 수집하기
- 변환하려는 영상이 있는 페이지에서 영상을 **재생**합니다. 요청이 시작되는 순간 수집되므로, 끝까지 볼 필요 없이 몇 초만 재생하고 다음 영상으로 넘어가도 됩니다.
- 수집되면 툴바 아이콘에 빨간 숫자 배지가 표시됩니다.
- 페이지 제목이 파일 이름의 기본값이 됩니다.

### 2) 수집함 열기
- 툴바 아이콘을 누르고 **수집함 열기 / 일괄 변환**을 누릅니다.
- 주소를 이미 알고 있다면 팝업의 **링크 직접 추가**에 영상 파일 주소(`.mp4` 등)를 넣어 수집함에 추가할 수 있습니다. (현재 보고 있는 탭 주소가 Referer로 사용됩니다)

### 3) 설정 후 변환
| 설정 | 설명 |
| --- | --- |
| **저장 위치** | `폴더 선택...`으로 폴더를 직접 고르면 그 폴더에 바로 저장됩니다. 고르지 않으면 크롬 기본 다운로드 폴더(하위 폴더 이름 지정 가능)에 저장됩니다. |
| **품질** | `음성(빠름·작은 용량)`: 모노 / 22.05kHz / 64kbps. 강의·회의 등 음성에 적합. `표준`: 스테레오 / 44.1kHz / 128kbps. 음악 등에 적합. |
| **동시 처리** | 동시에 처리할 영상 수(1~4). 긴 영상이 많으면 메모리를 많이 쓰므로 1~2 권장. |
| **다운로드 연결** | 한 영상을 몇 개의 연결로 나눠 받을지(1/4/8/16). 서버가 분할 요청을 지원할 때만 효과가 있습니다. |
| **파일명에 번호 붙이기** | `01_이름.mp3`, `02_이름.mp3` … 순서대로 번호를 붙입니다. |

1. 변환할 항목의 체크박스를 선택합니다. (기본은 전체 선택)
2. 파일 이름은 입력칸에서 직접 고칠 수 있습니다.
3. **선택 항목 변환 시작**을 누릅니다.
4. 각 항목에 `다운로드 → 오디오 추출 → MP3 인코딩 → 저장` 진행 상황이 표시됩니다.
5. 끝난 항목은 선택이 풀리고 아래 **✅ 완료** 구역으로 이동합니다. (↩ 버튼으로 다시 대기열에 넣을 수 있습니다)

### 4) 기타
- **중지**: 대기 중인 항목을 취소합니다. 이미 진행 중인 항목은 끝까지 처리됩니다.
- **✕**: 목록에서 삭제(진행 중이면 취소). **완료 항목 비우기** / **전체 비우기**도 있습니다.
- 수집 목록은 브라우저를 닫아도 유지됩니다. 영상 주소가 시간이 지나 만료될 수 있으니 오래된 목록은 비우고 다시 수집하세요.

## 제한 사항

- **YouTube 등 스트리밍 사이트는 지원하지 않습니다.** 조각 단위 전송·DRM 보호 영상은 변환할 수 없고, 이런 사이트에서 내려받는 것은 이용약관에 어긋날 수 있습니다.
- **m3u8(HLS)** 스트림은 수집하지 않습니다. (`.mp4`, `.webm`, `.mp3`, `.m4a` 같은 일반 파일 주소만 대상)
- 영상 전체를 메모리에 올려 디코딩하므로 아주 큰 파일(1GB 이상)은 느리거나 실패할 수 있습니다.
- **크롬을 완전히 종료하거나 확장 프로그램을 새로고침하면 진행 중이던 작업이 멈춥니다.** 다시 시작하면 완료된 항목은 건너뜁니다.
- 폴더를 직접 선택한 경우, 크롬을 다시 켠 뒤에는 **변환 시작을 누를 때** 폴더 쓰기 권한 확인이 한 번 나옵니다. 권한이 없으면 기본 다운로드 폴더로 저장하고 그 항목에 안내 문구가 표시됩니다.
- 크롬은 보안상 **다운로드·바탕화면·문서 폴더 자체**는 저장 폴더로 선택하지 못하게 합니다. 그 안에 새 폴더를 만들어 선택하세요.
- 병렬 인코딩으로 이어 붙인 지점에는 약 0.05초 정도의 미세한 차이가 생길 수 있습니다. (조용한 구간에서 자르므로 거의 들리지 않습니다)

## 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| 수집함에 아무것도 안 나타난다 | 영상을 **재생**했는지 확인하세요. 페이지가 `.m3u8`/DRM 방식이면 수집되지 않습니다. 개발자 도구(F12) → Network → `Media` 필터에서 `.mp4` 같은 요청이 보이는지 확인해 보세요. |
| `다운로드 실패 (HTTP 403)` | 서버가 Referer를 검사하는 경우입니다. **재생 중이던 페이지에서 수집된 항목**으로 시도하세요. 직접 추가한 링크는 현재 탭 주소가 Referer로 쓰입니다. 그래도 안 되면 로그인 상태에서 영상을 재생한 직후 다시 시도하세요. |
| `오디오 디코딩 불가` | 지원하지 않는 형식이거나 DRM 보호 영상입니다. |
| 다운로드가 느리다 | 항목에 표시되는 `[병렬 N연결]`·`MB/s`를 확인하세요. `[단일 연결]`이면 서버가 분할 요청을 지원하지 않는 것입니다. 이때는 동시 처리 수를 늘리는 쪽이 더 낫습니다. |
| 폴더에 저장되지 않고 다운로드 폴더로 간다 | 폴더 쓰기 권한이 없는 경우입니다. 폴더를 다시 선택하고 변환 시작을 눌러 권한을 허용하세요. |
| 브라우저가 무거워진다 | 동시 처리 수를 1~2로 낮추세요. |

## 요구 권한

| 권한 | 용도 |
| --- | --- |
| `webRequest` + `<all_urls>` | 재생 중인 영상/오디오 요청 감지, 영상 서버에 요청 |
| `tabs` | 영상이 재생된 탭의 제목·주소(파일 이름, Referer) 확인 |
| `storage` | 수집 목록, 파일명, 완료 기록, 설정 저장 |
| `downloads` | 기본 다운로드 폴더로 MP3 저장 |
| `declarativeNetRequest` | 변환 요청에 Referer/Origin 헤더 추가 |
| `offscreen` | 수집함 탭과 무관하게 계속 도는 백그라운드 변환 처리기 |

데이터는 모두 브라우저 안에서만 처리되며, 외부 서버로 전송하지 않습니다.

## 프로젝트 구조

```
├── manifest.json        # 확장 프로그램 설정 (Manifest V3)
├── background.js        # 미디어 요청 수집, 크롬 API 중계(다운로드·헤더 규칙·완료 기록)
├── popup.html / .js     # 툴바 팝업 (수집함 열기, 링크 직접 추가)
├── manager.html / .js   # 수집함 화면 (목록·설정·진행 상황 표시)
├── offscreen.html / .js # 백그라운드 처리기: 다운로드 → 디코딩 → 병렬 인코딩 → 저장
├── encoder-worker.js    # MP3 인코딩 워커 (코어 수만큼 풀로 운영)
├── lame.min.js          # MP3 인코더 (lamejs, LGPL-3.0 — 일부 수정, THIRD_PARTY_NOTICES.md 참고)
├── icons/               # 확장 프로그램 아이콘
└── docs/logo.png        # README용 로고
```

## 동작 방식

1. `background.js`가 `webRequest`로 영상/오디오 응답을 감지해 `chrome.storage.local`에 저장합니다.
2. 수집함(`manager.js`)에서 변환을 시작하면 `offscreen.js`로 작업을 보냅니다. (수집함은 화면만 담당)
3. `offscreen.js`가 파일을 받고(가능하면 Range 요청으로 병렬), `AudioContext.decodeAudioData`로 오디오를 추출합니다.
4. 오디오를 조용한 지점에서 구간으로 나눠 `encoder-worker.js`들에서 동시에 MP3로 인코딩하고 이어 붙입니다.
5. 선택한 폴더(File System Access API) 또는 `chrome.downloads`로 저장합니다.

## 사용 시 주의

본인이 권리를 가진 콘텐츠이거나 다운로드가 허용된 콘텐츠에만 사용하세요. 저작권이 있는 영상(예: 학교 강의)은 개인 학습 범위를 넘어 공유·배포하면 안 됩니다. 서비스 약관과 저작권 책임은 사용자에게 있습니다.
